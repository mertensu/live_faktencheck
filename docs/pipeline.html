Vom Audio zum Faktencheck

Jeder Transkript-Block durchläuft sechs Stufen. Fünf davon sind Prompts an ein Sprachmodell — hier steht zu jeder, was reingeht (Input) und was rauskommt (Output).

🎙 Audio → 1 Transkript → 2 Namen → 3 Extraktion → 4 Auswahl → 5 Check → 6 Kritik
1

Transkription

AssemblyAI · universal-3-pro

Wandelt den Audioblock in Text um — mit deutscher Spracherkennung und Sprechertrennung. Kein Prompt, ein Speech-Model. Gäste-Namen werden als keyterms mitgegeben, damit Eigennamen korrekt erkannt werden.

Input

audio_data bytesWebM/Opus, MP4 oder WAV keyterms list[str]Namen + Partei/Org aus der Gästeliste

Output

transcript str duration float Sekunden
Format je Redebeitrag: Sprecher A: Die Inflation lag bei acht Prozent. Sprecher B: Das hat die Rente gekostet.
2

Sprecher-Namen auflösen

Gemini 2.5 Flash speaker_labels.md

Ordnet den generischen Labels („Sprecher A") die echten Namen zu. Die zwei Quellen dafür stecken direkt im Input: der Gesprächsverlauf ist das transcript, die Rollen/Parteien stehen im guests-Feld — Gäste sind als „Name (Partei/Org, Rolle)" formatiert. Das Modell gibt nur die Zuordnungstabelle zurück; der Code ersetzt die Labels danach im Transkript (längste zuerst).

Input — JSON

conversation_type strdebate · interview · private guests list[str]„Name (Partei/Org, Rolle)" → liefert die Rollen/Parteien transcript str „Sprecher A/B…" → liefert den Gesprächsverlauf
guests, z. B.: ["Caren Miosga (Moderatorin)", "Heidi Reichinnek (Linke)"]

Output — ResolvedTranscript

mappings list label str „Sprecher A" name str „Julia Berger"
Ergebnis nach Ersetzung: Julia Berger: Die Inflation lag bei acht Prozent.
3

Behauptungen extrahieren

Gemini 2.5 Flash claim_extraction.md

Zieht überprüfbare Tatsachenbehauptungen aus dem aufgelösten Transkript. Zwei Kernregeln: Dekontextualisierung (Pronomen → volle Namen, damit jede Behauptung allein prüfbar ist) und Zerlegung (gebündelte Fakt+Ursache oder Fakt+Fakt werden getrennt). Aussagen von excluded_speakers (z. B. Moderation) werden ignoriert.

Input — JSON

conversation_type str guests list[str] context str Thema der Sendung excluded_speakers list[str] transcript str aufgelöst (Stufe 2) previous_block_ending str?nur zur Kontinuität, nicht extrahiert

Output — ClaimList

claims List[ExtractedClaim] ExtractedClaim { name str Sprecher (Eigenname) claim str eigenständige Behauptung }
z. B. aus einem Satz → 2 Claims: 1. Julia Berger: Die Inflation lag 2023 bei 8 %. 2. Julia Berger: Die Inflation verursachte Rentenverluste.
4

Prüfwürdige auswählen

Gemini 2.5 Flash claim_selection.md

Filtert aus der Claim-Liste alle prüfwürdigen Behauptungen — substanziell und öffentlich/politisch relevant; Triviales fällt weg. Keine feste Anzahl (0, 1 oder viele). Gibt die Claims unverändert zurück.

⑃ Diese Stufe läuft nur im Autopilot. Im normalen Betrieb prüft stattdessen die Redaktion in der Admin-UI die Claims aus Stufe 3 manuell und gibt sie frei.

Input — Klartext-Liste

Nummerierte Liste der extrahierten Claims:
Behauptungen: 1. [Julia Berger]: Die Inflation lag 2023 bei 8 %. 2. [Max Klein]: Der Himmel ist blau.

Output — ClaimList

Teilmenge derselben Claims (hier fällt #2 als trivial weg).

Safety-Cap: max. AUTO_SELECT_MAX = 6 Fact-Checks pro Block.

5

Faktencheck

Gemini 2.5 Pro · ReAct-Agent fact_checker.md

Prüft jede Behauptung einzeln. Ein ReAct-Agent (denken → suchen → denken → Urteil) mit dem Tool tavily_search, das nur vertrauenswürdige deutsche Domains durchsucht. Der Prompt verlangt Primärquellen, aktive Gegenbeweis-Suche und verbietet absolute Urteile („wahr/falsch"). {current_date} wird pro Lauf eingesetzt.

Input — JSON (ClaimInput)

context str Thema der Sendung sprecher str sendedatum str „März 2026" behauptung str

🔧 Tool tavily_search(query, start_date?, end_date?) — wird im Loop mehrfach aufgerufen.

Output — FactCheckResponse

speaker str original_claim str consistency enum evidence str strukturierte Begründung sources list url + title
hoch niedrig unklar keine Datenlage
6

Selbstkritik

Gemini 2.5 Flash self_critique.md

Ein separater Reviewer bewertet, wie robust das Urteil aus Stufe 5 ist — nur anhand der Begründung. Er überschreibt das Urteil nie, sondern markiert es: bei confidence = low setzt der Code double_check = true (Signal für die Redaktion).

Input — JSON (SelfCritiqueInput)

behauptung str urteil enum consistency aus Stufe 5 begruendung str evidence aus Stufe 5

Output — SelfCritiqueResponse

confidence enum high · low reason str 1 Satz: warum (nicht) robust
high → normal low → double_check
◆ Ergebnis geht an das Dashboard: Behauptung, Konsistenz-Urteil, Begründung, Quellen und ggf. die „Doppelt prüfen"-Markierung.
Modelle konfigurierbar per .env:
GEMINI_MODEL_CLAIM_EXTRACTION · GEMINI_MODEL_FACT_CHECKER · GEMINI_MODEL_SELF_CRITIQUE
Prompts: prompts/*.md  ·  Feld-Beschreibungen (Sprache): backend/lang.py
Services: claim_extraction.py (Stufe 2–4) · fact_checker.py (Stufe 5–6) · transcription.py (Stufe 1)
